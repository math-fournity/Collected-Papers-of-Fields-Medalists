## 1. 冻结结论

旧批次 P01–P40 的结果已按实物分类，而不是按“曾派发”分类：29 篇已完成并处于 canonical `main`（包括先前已经集成的 P03）；6 篇已将现有审计证据收割到主线、但仍不满足完成条件；P37 因 PDF↔MinerU 映射错误阻塞；P40 只到 p.118/127 且存在方法范围冲突，保留候选但不集成；P10、P12、P30 没有可发现的候选论文产物。P41–P65 的 25 个异步创建请求只有 provisional `clientThreadId`/派发记录，未发现可验证的正式 task、worktree 或候选提交，因此不计为已开始。更早的非编号 Witten、Deng 与 Drinfeld Peer 也已复核并各自完整收割，不能遗漏于 P01–P65 的统计之外。

所有被收割的候选均以其 source OID 做以下预检：候选 diff 不触碰根级 current-truth 文件、与当时 `main` 无路径重叠、`git merge-tree --write-tree` 为 clean；集成时复跑 staged `git diff --check`。P34 的新 AUDIT 记录有 11 处行尾空白，Master 仅清除了这些审计文档排版空白后才提交；没有改动它的 MinerU Markdown。

旧 worker worktree 没有被本次收割删除、archive、clean 或 reset。其未提交文件仍留在原 worktree，未被“顺手”带入主线。

## 7. 后续调度边界

用户已指定后续不再继续旧 project-peer 方式。依照 `rulings.md#R-004/#R-005`，ZCode 在用户明确确认的 scope 内可以选择独立 worktree 的 Codex CLI App Server，或其当前 runtime 实际支持且另获 exact envelope 的原生 Sub Agent。确认前不得启动 App Server、control-plane pilot、Sub Agent 或论文工作；若选择 App Server，仍先通过**不触及论文内容**的 start/observe/steer/restart/resume 资格化，且 pilot 通过后还需再次确认论文 worker。旧 `clientThreadId` 不能转换为 App Server `thread.id`，冻结任务也不得因切换控制器而重复派发。

详细的控制面设计与其未验证边界见 [001 — Codex App Server 并发 Peer 工作流调查与试点方案](001-2026-10-02-Codex-App-Server并发Peer工作流调查与试点方案.md)。
